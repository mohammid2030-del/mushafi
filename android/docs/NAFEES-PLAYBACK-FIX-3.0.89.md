# Nafees complete-file playback correction — 3.0.89 (139)

The 3.0.88 addition trusted the publisher timing API after structural checks (row count/order, interval validity, final duration containment and matching folder identity). These checks did not establish that the timings aligned with the spoken recording. Baqarah publisher verse 1 begins at 59.72s, although the chapter opening has already been recited before that time. Subtracting this offset hid the skipped opening behind logical 00:00. End trimming and individual verse clips consequently could also cut or mislabel speech. The 3.0.88 Fatiha-only exception did not address the broader mismatch.

All 114 Nafees chapters now play the original entire file from zero: audioOffsetMs=0, trimToTimings=false, verseTimingVerified=false and no active timing rows. Duration comes from the media player; catalog header estimates are only metadata. Canonical verseCount is separate so sequential completion advances to the next chapter and random completion chooses another chapter at file zero. Single mode is explicitly “this chapter only” for this reader. Changing shuffle mid-chapter waits for natural file completion. Native restored Nafees positions from the older logical timeline reset once via timelineRevision=full-file-v2; current-version pause/resume positions remain usable.

No invented corrections, ASR-generated verse boundaries, borrowed timings, wrong verse highlights or tafsir synchronization are shipped for Nafees. All 6236 isolated ayahs are explicitly unavailable, with an Arabic/English explanation. Full-chapter listening and his portrait remain in Home, More, Welcome and system media artwork. Both Home and More remove the unavailable follow mode; the full player shows the portrait, chapter navigation, and an availability note. Ayah clips/downloads are blocked in browser and native source validation. Full-file cached audio remains usable because its bytes/source are unchanged.

The raw publisher timing reports remain only in docs for diagnosis. A public Baqarah prefix fixture (bytes 0–2097151) preserves the actual opening for browser regression. A diagnostic tiny ASR with correct stereo-to-mono downmix recognizes istiadhah/basmalah in the opening eight seconds and later verses before 59s. This is diagnostic evidence, not a trusted transcript/alignment and supplies no shipped timestamps. See docs/sources/nafees-mp3quran/timing-rejection-3.0.89.json. The temporary ASR model/runtime is not shipped.

Validation: real Baqarah MP3 playback starts at file zero through an HTTP range fixture, preserves pause/resume, never shows unverified ayah labels, supports manual time seeking without false labels, and Home preserves the complete-file entry. Browser sequence tests cover natural sequential/random/single completion and last-chapter termination. Native unit checks reject all 6236 unverified requests, including a deliberately injected publisher timestamp, and exercise chapter completion selection. Existing nine reciters' full/inline catalogs compare equal to 3.0.88; their ayah/tafsir, playback modes and Home navigation regressions are checked. Eight Android release gates, signed APK/AAB parity and original signing certificate are checked during packaging. No physical Android/background audio test was available.
