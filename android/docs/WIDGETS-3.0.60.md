# 3.0.60 (110): compact widget layout and system time format

Fixes the reported large gaps inside prayer and remembrance home-screen widgets. The previous ImageView consumed all remaining height and its bitmap placed header/body/reference across that full height. The artwork now measures its natural content height, has a bounded compact prayer/date composition, and uses an intrinsic-height ImageView. A centered vertical group keeps the artwork, countdown and footer adjacent rather than spreading them apart when the launcher allocates a tall area. Text layout excludes extra font padding and preserves every source character. Compact resize minima/defaults are supplied to the launcher; existing home-screen grid allocation remains under launcher/user control and can be reduced by long press and resize.

The shared widget time formatter consults Android DateFormat.is24HourFormat. Prayer row and next prayer use HH:mm in system 24-hour mode, or h:mm a in 12-hour mode, localized to the widget language. The countdown is elapsed time and remains a duration. Existing time/locale broadcasts and platform refresh apply the format without resetting per-widget appearance.

Native QA extends existing three-provider, configuration cancel/save, prayer-boundary and canonical-data tests. It changes the actual Android time_12_24 system preference to 12 and 24, checks both prayer row and heading, and restores it. Native RemoteViews are rendered in both languages, all three themes, and short/tall widths/heights. Regression assertions ensure artwork stays bounded in a tall widget and countdown/footer are adjacent. Three remembrance texts are rendered at a tall transparent size matching the reported problem. Native picker previews are regenerated from the corrected renderer.

No prayer calculation, location, sync, Quran data, tafsir or playback/timing changes. All six release data gates and existing signing identity are retained. Verification uses API29 and does not claim testing every OEM launcher.
