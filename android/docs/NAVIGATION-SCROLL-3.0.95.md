# Section viewport memory — 3.0.95 (145)

The previous enterSection always scrolled to zero, while the glass navigation ignored a repeated activation of its selected root. Now a repeated activation of Home/Quran/Azkar/Library/More scrolls the active root to zero with native smooth scrolling (instant when motion is disabled), without rerendering or clearing its search. Changing tabs restores each root's previous position instead. Explicit headers and native/system Back use the same screen restoration.

navigation-scroll.js wraps the existing navigation contract after all controllers load. Before leaving, an ephemeral bounded map captures window position, a stable visible anchor/offset, search queries, expanded details and nested scroll positions. A pre-paint restore and short ResizeObserver/font-ready window handle rebuilt or asynchronous content. Anchors keep the entry card in the same viewport position when content above it changes. Search restoration replays only input filtering; settings, select values, checkboxes and business state are never replayed. Charity open-state restoration is instant and does not trigger its opening alignment animation. Rapid navigation cancels stale observers/frames, and an intermediate screen that has not restored yet cannot overwrite its last painted position. User scroll/keyboard intent cancels deferred restoration.

Full-screen Quran/dhikr/listening and onboarding keep their established controllers rather than inheriting document scroll restoration. Home recitation's modal/full-screen return remains intact. The cache is session-local, capped at 120 recent screen contexts, and does not add account/sync data.
