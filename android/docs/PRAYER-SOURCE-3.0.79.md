# Global prayer source 3.0.79 (129)

AlAdhan monthly calendars can now supply prayer times for the selected coordinates, time zone, Asr school and calculation method. AUTO lets the provider select a regional method. Riyadh/Makkah fixtures resolve to Umm al-Qura; Cairo to Egyptian; Dubai/Kuwait/Qatar to their regional profiles; Karachi, Singapore, Jakarta, New York and Europe use their corresponding provider profiles. This is a computational service, NOT a verified official government timetable for every country; 100% worldwide agreement is not claimed. Saudi official calendar pages were not reachable from this execution environment, so an independent official Saudi comparison is not claimed.

The bounded background HTTP worker fetches complete calendars over HTTPS with explicit ISO timestamps/offsets, validates dates/coordinates/method/school/order, and persists only complete valid results. ISO offsets preserve DST and timezone conversion. AlAdhan's same-date representation of Isha after midnight is normalized to the following day. Incomplete, duplicate, malformed, wrong-location or wrong-school data is rejected. Pending fetches do not overwrite changed settings. No network blocks the calculator or alarm delivery.

PrayerCalculator is the single source for screen, alarms, khatma prayer reminders and native widgets. A saved timetable is used only for the same method/school/timezone and within 500m of its requested coordinates. Missing data falls back to the existing local calculation with a regional suggestion, clearly marked as local. Unrecognized offline regions use MWL; that is a fallback, not a claim of local official adoption. Cached dates remain usable without a connection, refresh is attempted once a day/when needed, and sources/date/method are shown on the prayer screen and settings.

Existing Umm al-Qura default settings upgrade to regional AUTO once; non-default explicit methods remain manual. autoMethod is stored separately while method retains a legacy-compatible concrete value, avoiding an unknown enum in older sync clients. Manual method, Asr school, adjustments, iqama (Asr 20 minutes) and opt-out are preserved. New backup validation retains the two optional flags. Offline calculations now explicitly use Gregorian calendars independent of device locale (including Thai Buddhist defaults) and clear millisecond remnants when rounding.

Online-source control discloses coordinates being sent to api.aladhan.com without account details and allows local-only calculation. In-app sources/privacy and the full published privacy policy now describe the provider and caching. Policy version 2, 2026-10-30. Publishing the existing support project returned its canonical current host mushafi-support.mohammedasif241.chatgpt.site; support/CSP/weather contact and live-player host references use that same host with the existing strict path/origin checks. No support message was sent; only privacy GET and an empty locally rejected form were tested.
