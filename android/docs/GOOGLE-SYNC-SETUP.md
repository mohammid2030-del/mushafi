# ربط مصحفي بتسجيل قوقل والمزامنة

الإصدار 2.8 يربط قوقل باستخدام Credential Manager وFirebase Auth، ويحفظ البيانات في Cloud Firestore. تم تقديم ملف العميل المطابق للحزمة وبصمة التوقيع، وأكد المالك إنشاء القاعدة ونشر القواعد. جرى اختبار الصلاحيات بمحاكي Firestore، واختبار SDKs على أندرويد بهويات اختبار، واختبار واجهة جهازين. الدخول الفعلي بحساب قوقل يحتاج تجربة صاحب الحساب على جهاز يحتوي خدمات Google Play.

## الإعداد المطلوب في حساب مالك التطبيق

1. افتح https://console.firebase.google.com/ وأنشئ مشروعًا باسم Mushafi. Google Analytics اختياري وليس مطلوبًا للمزامنة.
2. أضف تطبيق Android باسم الحزمة `com.mushafi.app`.
3. أضف بصمة SHA-1 لشهادة التحديث الحالية: `26:E6:B8:82:F0:13:BA:F0:73:D0:7C:E8:D9:15:5F:F7:8B:22:5F:22`.
4. أضف SHA-256: `6D:FD:6F:B3:E2:BA:FB:AE:5C:60:6E:8B:A3:EF:FA:8B:2F:A7:11:9F:0C:A3:8A:66:71:FA:00:EF:38:71:35:B3` (استخدم القيمة المتصلة أدناه إذا لم يقبل الحقل الفواصل).
   `6dfd6fb3e2bafbae5c606e8ba3effa8b2fa7119f0ca38a6671fa00ef387135b3`
5. من Authentication > Sign-in method فعّل Google وحدد بريد الدعم.
6. أنشئ Cloud Firestore في Production mode واختر المنطقة المناسبة قبل حفظ بيانات المستخدمين.
7. يلزم ملف إعداد تطبيق Android `google-services.json`، ومعرّف Web OAuth client المرتبط بموفّر Google. هذه إعدادات عميل؛ لا نحتاج كلمة مرور قوقل أو مفتاح حساب خدمة.

## نطاق البيانات المراد مزامنتها

- موضع القراءة العامة مستقل عن موضع الختمة وعن متابعة التلاوة.
- خطة الختمة والتقدم المتراجع أو المتقدم وآخر موضع داخل الورد.
- العلامات، ملاحظات الآيات، الأدعية المفضلة، تقدم الأذكار والعدّادات والورد اليومي.
- المظهر وحجم الخط وخيارات القراءة والمقرئ والتكرار.
- تفضيلات مواقيت الصلاة ومدد الإقامة. أذونات الإشعار والمنبه الدقيق تُمنح لكل جهاز؛ لا تُنسخ كصلاحيات.
- ملفات القرآن المضمّنة لا تحتاج رفعًا. ملفات الصوت المنزلة تبقى محلية لكل جهاز.

## شروط التنفيذ والتحقق

- يحتفظ كل مستخدم بمستندات مرتبطة بمعرّف Firebase UID الخاص به، ويمنع الوصول لبيانات مستخدم آخر.
- الهوية تُتحقق بخدمات Firebase، ولا يُعتد بالبريد المرسل من العميل كإثبات دخول.
- حفظ محلي أثناء انقطاع الاتصال، مع حالة آخر مزامنة ورسالة فشل قابلة لإعادة المحاولة.
- تحديث موضع القراءة حسب أحدث تعديل، بما فيه الرجوع من الصفحة 19 إلى 17؛ لا نستخدم أكبر رقم صفحة عند الدمج.
- تعريف طريقة حل تعارض التغييرات الصادرة من جهازين دون فقد الحذف أو إعادة إحياء علامات محذوفة.
- عدم نقل الحساب أو الرموز بين مستخدمين عند تسجيل الخروج. لا تُرفع أي بيانات قبل موافقة المستخدم على تسجيل الدخول والمزامنة.
- اختبار دخول فعلي بقوقل على جوال وتابلت، ثم قراءة وتعديل وحذف دون اتصال وإعادة الاتصال، والتحقق من منع وصول حساب إلى بيانات حساب آخر.

## قاعدة Firestore مبدئية يجب اختبارها قبل التفعيل

ملف `firestore.rules` يحصر المسار تحت UID. يُستكمل التحقق من حقول الوثائق وحدود حجمها وطريقة الدمج مع التنفيذ، ولا يُنشر وحده كخدمة مزامنة جاهزة.
