# مراجعة أمان مصحفي — 28 أكتوبر 2026

الإصدار الناتج: 3.0.32 (82). مراجعة للكود والحزمة واختبارات محددة، وليست شهادة حصانة أو اختبار اختراق شاملًا لكل خدمات Google والأجهزة.

## ما تم التحقق منه

- إعدادات الحساب: Google Credential Manager وFirebase Auth؛ كلمات المرور لا يطلبها التطبيق. رموز Google لا تُرسل إلى JavaScript. حذف الحساب يتطلب إعادة تحقق بالحساب نفسه، مع إيقاف المزامنة عند فشل الحذف جزئيًا.
- المزامنة: مسار مستقل لكل UID، والتحقق من جلسة الحساب ومن رقم مراجعة البيانات قبل الكتابة. البيانات المستعادة تمر على قائمة مفاتيح مسموحة وتحقيق للقيم، وتُسترجع الحالة عند فشل التطبيق.
- Firestore المحلي: تشغيل قواعد docs/firestore.rules الفعلية في المحاكي. نجاح منع القراءة/الكتابة/الحذف دون دخول ومن حساب آخر، والمسارات غير المسموحة، والحقول الزائدة أو الناقصة، والحجم والنوع غير الصحيحين، والمراجعات القديمة/القافزة، والتوقيت غير الصادر عن الخادم. اختبار حسابين وتعارض المعاملات نجح. لم تُغيّر القواعد ولم تُنشر قواعد جديدة.
- Firestore المنشور: طلبا GET بلا مصادقة لمسارين عشوائيين غير موجودين، أحدهما تحت users والآخر مسار عام؛ أعادا HTTP 403. لم يُقرأ أي مستند لمستخدم حقيقي، ولم تتم كتابة بيانات على الإنتاج. هذا يثبت رفض هذين الطلبين فقط، ولا يكشف جميع القواعد المنشورة أو إعدادات الإدارة.
- فحص APK: لا ملفات توقيع/keystore أو مفاتيح حساب خدمة خاصة في الأسماء والمحتويات المفحوصة. مفاتيح إعداد Firebase العامة ليست مفاتيح إدارة؛ قيودها في Google Cloud لم تُفحص. النسخة المصدرية تستبعد مجلد signing.
- النسخ الاحتياطي التلقائي للنظام معطّل. الملفات في مساحة التطبيق الخاصة؛ لا إذن كاميرا أو ميكروفون أو جهات اتصال. مكوّنات الصوت والتنبيهات غير مصدّرة، وPendingIntent غير قابل للتعديل. نشاط Firebase الخارجي جزء من المكتبة؛ لا يُصنّف ثغرة لمجرد كونه مصدّرًا.
- البث الخارجي في WebView منفصل بلا AndroidReader، مع منع الملفات والمحتوى المختلط وإلغاء أخطاء TLS ورفض طلبات الكاميرا/الميكروفون/الموقع.

## التقوية المضافة

- منع cleartext HTTP صراحةً بما يشمل Android 6/7 المدعومين.
- WebView الرئيسي: منع الوصول العام للملفات وcontent، ومنع توسيع أذونات file URL والمحتوى المختلط وفتح النوافذ تلقائيًا، وتعطيل تحديد الموقع عبر صفحات الويب. الموقع الأصلي يبقى عبر الإذن والنظام.
- قصر التنقل الرئيسي إلى وثيقة التطبيق المعروفة أو وثيقة ترحيل البيانات القديمة؛ التحميل المحلي للصور والخطوط وJSON مستمر عبر خادم الأصول الداخلي.
- إضافة CSP لواجهات التطبيق المحلية: منع eval والسكربتات البعيدة والإطارات والكائنات وتغيير base وإرسال forms مباشرة. السكربتات ومعالجات الأحداث المحلية المضمنة ما زالت مسموحة حسب بنية التطبيق؛ السياسة لا تعوّض تعقيم النصوص.
- شاشة التحميل لا تسمح بتنقل الويب إلى صفحات أخرى.

## التحقق وحدوده

نجحت اختبارات CSP في Chromium، والتعامل مع أسماء وملاحظات تحتوي HTML، ورفض بيانات النسخ الخبيثة/المجهولة. نجحت اختبارات المزامنة وتغيّر الحسابات وشاشة البداية والقواعد المحلية. إصدار APK/AAB موقّع بشهادة التطبيق نفسها؛ فحص الحزمة النهائي موثّق في ملف الإصدار.

لا توجد صلاحيات إدارة Firebase في بيئة العمل: لم تتحقق قيود API key أو إعدادات مزود الدخول أو App Check أو الحصص/التنبيهات والفوترة أو مطابقة كل القواعد المنشورة. App Check/Play Integrity غير مدمج حاليًا في الكود؛ يوصى بتقييمه بعد إعداد Play Console، ولا يعوّض قواعد صلاحيات الحساب.

الكود وملفات JavaScript قابلة للاستخراج؛ minifyEnabled ما زال false. التوقيع يمنع التحديث فوق النسخة الأصلية بشهادة أخرى، ولا يمنع إعادة توقيع نسخة معدّلة. لم يُضف تمويه شكلي ليُقدّم على أنه حماية للبيانات. التخزين المحلي ليس مشفرًا بتشفير خاص بالتطبيق، ويعتمد على عزل Android وحماية الجهاز؛ لم يُختبر جهاز مروّت أو جهاز Samsung فعلي في هذه المراجعة. لم يُنفّذ مسح شامل لثغرات سلسلة التوريد أو حمل/حجب خدمة أو اختراق حسابات حقيقية.
