# English-only adhkar with pronunciation — 3.0.46 (96)

The user requested Latin-letter pronunciation guidance for every selected dhikr, including Quran verses within adhkar, then clarified that Arabic text must not appear in English mode. All 195 selected entries now show a pronunciation guide followed by the existing English meaning. Lists, favorites, category/global search and English sharing follow the same mode. Original Arabic is preserved in the canonical dataset and restored when Arabic is selected. Arabic text is hidden through both layout and hidden attributes where the reader is active; it is not merely faded or overlaid. The home caption and tasbih display/option labels are English-only. Tasbih option values and saved phrases remain Arabic for data compatibility.

The guides use accessible Latin spelling: aa/ee/oo for long vowels, kh/gh/sh/th/dh for consonant approximations, and apostrophes for guttural/glottal boundaries. They were prepared editorially against the exact bundled Arabic excerpts, retaining alternative wording and pronouns. They are approximations, not a claim of complete tajwid representation or independent scholarly/phonetic certification. The reading interface says that some Arabic sounds have no exact English equivalent. Neither system speech synthesis nor generated Quran audio is used.

There are 153 non-Quran entries and 42 Quran entries. The latter share 51 unique canonical verse keys plus the basmalah, with exact original block order and basmalah placement. The Quran guides are editorial text tied to those keys and Arabic source hashes. Public comparison sources inspected were Tanzil en.transliteration and the Islamic Network en.transliteration API; defects observed in the external data, including repeated wording in 21:87 and malformed words in 2:255 and 46:15, were not copied. No third-party transliteration corpus is redistributed as an app asset. The existing English meanings remain byte-identical to 3.0.45.

Quran verses within adhkar have individual Listen buttons. These call the existing recorded-verse player with the exact chapter:verse key and existing selectable reciters. The sheet shows Latin pronunciation in English mode and original Arabic in Arabic mode. Closing it stops the recording. It does not mark a dhikr read, increment counts, navigate to another section or change main/khatma reading positions. Recordings use the existing online/cache behavior; the pronunciation and meaning texts are bundled offline. This release does not claim new recorded audio for every non-Quran supplication. The separate full local Sahih Muslim corpus remains Arabic; its local full-hadith link is only shown in Arabic mode from an adhkar source panel.

Data provenance: docs/sources/adhkar-pronunciation-editorial.json; runtime assets/adhkar-pronunciation-data.js. The Gradle release gate and tools/verify-adhkar-pronunciation.cjs verify all 195 IDs, unchanged Arabic data hashes, canonical Quran keys, consistent basmalah blocks and complete Latin strings against the retained editorial text. These checks establish integrity and coverage, not independent linguistic certification.

Validation: all 195 English-only readers/source panels/share payloads; all Quran guide keys; native bridge commands for 2:255 and stop on close; no counter/anchor changes from listening; reversible Arabic/English switching without replacing the Arabic reader node or losing progress; font scaling/reset; English-only tasbih option labels with stable Arabic storage; 320/393/740/1280 portrait/landscape layouts and long-guide scrolling. Existing adhkar meanings, English UI, Arabic counting/auto-advance and English Quran regression suites were also run. Native player implementation is unchanged; browser bridge tests do not claim a physical-device playback test.
