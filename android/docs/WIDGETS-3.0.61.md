# 3.0.61 (111): actual resizing and Western countdown digits

Fixes the supplied screenshots where the resize frame shrank but the prayer row/countdown/footer remained outside it. The old intrinsic-height ImageView had no mechanism to surrender height before pushing subsequent children outside a centered root. A bounded FrameLayout now contains a wrap-content vertical panel whose weighted artwork shrinks first. Its image matrix adapts to the actual host bounds even while launcher option values are stale. Timer and footer retain their measured height inside those bounds; large widgets remain compact. Minimum resize dimensions are reduced to 120×80dp. A short prayer variant prioritizes next prayer/time and countdown; the full five-time row returns in the larger variant. Decorative footer is hidden in the shortest variant.

Size-change callbacks use their supplied options immediately. API31+ uses the launcher-provided SizeF variants (up to four); older hosts use portrait/landscape RemoteViews rather than guessing the launcher's orientation from the app context. The new mushafi_widget_responsive layout has a distinct resource ID, forcing existing hosts to replace the previous cached layout and apply the new panel/font without removing and re-adding the widget.

Android Chronometer localizes its generated text in the launcher's process; setting only the app locale or textLocale cannot ensure Western digits. A licensed, renamed numeric subset of the existing Noto UI font maps Arabic-Indic and extended Arabic-Indic digits to the exact existing Western digit glyphs. Chronometer continues native ticking with no per-second worker or battery-intensive broadcast loop. Its numeric typeface has compact Latin metrics and is scoped to the countdown. Quran, Arabic UI fonts and all source data are untouched. Full OFL license and copyright are distributed in assets/licenses/widget-digits-ofl.txt; tools/build-widget-digits.py reproduces the face. On pre-26 Android, where framework resource font loading is unavailable, the existing timestamp fallback is shown rather than an incorrectly localized counter.

QA extends the real API29 host suite: keep metadata at 300×440 while physically resizing the host through large/small/large bounds, verify all visible children stay inside, and assert artwork matrix actually shrinks. Exercise compact metadata, real existing-host layout replacement, and both clock modes. With the actual styled native Chronometer and an Arabic process locale, rasterize Arabic-Indic and ASCII sample countdowns and require byte-identical Western glyph pixels. Existing three-provider, RTL/LTR/theme, config save/cancel, data and prayer-boundary tests retained. API31 SizeF routing is compiled; physical Samsung launcher testing is not available in this environment.

All six data gates, existing release signing identity and playback/ayah/tafsir sync data are preserved. No new permission, service or account/network dependency.
