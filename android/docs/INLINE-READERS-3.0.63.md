# 3.0.63 (113): all nine reciters in isolated ayah listening

The Mushaf's single-ayah picker was hardcoded to four reciters while full-surah listening had nine. It now derives its choices from the complete inline catalog, with the four existing readers first. Adds Abdurrahman As-Sudais, Ali Al-Hudhaifi, Muhammad Ayyub, Khalid Al-Muhanna and Ibrahim Al-Akhdar, including all 6236 individually addressed verses each. Backup and cloud snapshot validators use the same available-reader list, preserving the new choices instead of rejecting them under the old three/four-reader limits. Account protocol and server rules are unchanged. Existing four source catalogs, their names/URLs and caches are preserved; adds English metadata for the two old labels that lacked translations.

The EveryAyah recitation registry and complete directory listings identify Sudais 192kbps and Hudhaify 128kbps. The three other readers use the publisher's original individual verse MP3 entries in Quran Complex's public Hafs archives. Each entry is pinned to its central-directory offset, compressed/uncompressed size, CRC and the SHA256 from the previously completed every-verse waveform verification ledger. The known Muhanna An-Nasr three-file 109/110 label correction is retained. No guessed per-verse URL and no chapter seek/cut approximation is used.

The native engine downloads only the selected ZIP entry with bounded HTTPS ranges (maximum 512KiB per request), verifies local-header method/encryption, response 206 and Content-Range/total, exact bounded decompression, CRC and SHA256, then atomically caches the original MP3. It rejects servers ignoring Range, partial/corrupt content and unexpected hosts. Publisher caches have a separate namespace and pinned clip hash in the filename. Other four caches are kept. The same extraction supports existing optional chapter downloads. UI shows ordinary preparation/progress; no archive implementation details enter the product flow.

Native asynchronous fetches have a per-play generation and cancellation; stop, pause, reader change and activity teardown prevent delayed playback. Individual-verse playback retains its page, uses its existing repeat count, and never opens full-surah listening or advances to the next verse. Full-surah data, timing/tafsir source, portraits, progress, widget layout and countdown are unchanged.

Browser fallback uses bounded HTTP ranges, bounded deflate-raw decompression and SHA256 before making an audio Blob. CSP adds only the exact publisher HTTPS host to connect-src and blob to media-src. Native playback remains the production Android path.

verifyInlineReaders is a seventh release gate: inline/native UI catalogs agree; every full-surah reciter has all canonical keys; all publisher clip hashes match the existing validation ledger; and all four original catalogs match their preserved commitments. New source registry/listing provenance is recorded in docs/sources/inline-readers-3.0.63.json.
